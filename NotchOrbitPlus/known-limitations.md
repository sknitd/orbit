# NotchOrbitPlus known limitations

Implemented source, executed fixtures, connected accounts, physical Mac interaction and trusted distribution are separate evidence. [EVALUATION.md](EVALUATION.md) records the exact verified build and acceptance still outstanding.

- MediaRemote is a private framework and its behavior can change. Direct access may be restricted on macOS 15.4 and later; the System source reports unavailable information instead of impersonating an entitled process. Music/Spotify are the supported fallback. Browser/player discovery on a user's Mac still needs acceptance.
- LRCLIB is a third-party provider. Lookup requires explicit opt-in and a click, sends title/artist/album/duration when available, and may return no matching lyrics. Local LRC import remains available; automatic requests on track changes are not performed.
- Hardware volume and brightness controls depend on the active device/display. Fixed-volume outputs and unsupported external displays keep the system HUD path. Media-key pairing, keyboard hardware and permission revocation require physical Mac verification.
- Screen recording is silent and intentionally short; capture resolution/duration bounds are enforced. No protected-content capture or audio recording is claimed. Real Screen Recording prompts, screen/window selection, Retina/multiple displays and resulting recordings require Mac acceptance.
- Battery data depends on what IOKit/Bluetooth devices expose. Missing AirPods/peripheral battery values stay unavailable. A running CoreAudio input device is labeled as input activity, not proof of a particular application's recording. Camera/Focus information can be unavailable through supported APIs. Focus reports only the authorized shared boolean; it does not identify a specific Focus mode or infer Do Not Disturb from private preferences.
- Local tunnel interfaces are indicators of VPN/tunnel activity, not a security guarantee or complete identification of every VPN provider. Network counters and active-interface selection require acceptance under real interface changes.
- GitHub Actions requires a user token with access to the intended repositories. It is read-only and bounded; API permissions, rate limits and real accounts were not established by fixtures. Currency dates come from the provider and may precede today.
- Legacy focus counts cannot reconstruct historical sessions. New history records completed focus sessions; corrupt original history is preserved. DST ambiguities and Calendar integration need user-Mac acceptance alongside portable date tests.
- Space placement uses public window collection behavior. It does not enumerate private Space IDs or sync display geometry. Fullscreen detection needs separately granted Accessibility access and leaves unknown windows/displays visible.
- Sync relies on a user-selected folder provider. Absolute paths/security bookmarks never travel between Macs; folders must be relinked locally, applications resolved by bundle ID and Shortcuts available on each Mac. Clipboard, credentials and pick history stay local. Concurrent launcher/workflow/palette edits preserve whole-category variants for explicit resolution, rather than merging individual list items collaboratively. All syncing Macs need 0.3.0: it reads version-1 snapshots and writes version 2, which 0.2.0 rejects safely. Provider delivery and two physical Macs were not tested by local fixtures.
- AppIntents run the app in the foreground. File inputs are regular files of at most 100 MB. Memory-backed workflow input publishes results to Downloads before its private input is removed. Actual Shortcuts discovery/execution and permission prompts require acceptance on an installed Mac.
- CPU/RSS evidence measures an idle CI Mac for a finite interval. It does not establish every Intel/Mac model, prolonged uptime, battery impact or 60/120 Hz responsiveness. VoiceOver, keyboard focus in embedded editors, Reduce Motion, Spaces and fullscreen require interactive acceptance.
- Development packages are ad hoc signed unless Apple Developer credentials are supplied securely to CI. Notarization/stapling and trusted automatic installation require those credentials and a signed/notarized release; an ad hoc build supports verified downloads and manual installation.
- Existing eligible-hardware Apple Intelligence, merchant accounts, stock credentials, camera, Reminders, Automation and AirDrop acceptance remain outstanding as documented in the evaluation.
