# Known limitations and physical Mac acceptance

- The app requires macOS 14+. The release is universal arm64/x86_64 and ad hoc signed; it is not Developer ID signed or notarized. Installation of a quarantined download on macOS 14 and an Intel Mac still needs physical acceptance.
- Real Input Monitoring/Accessibility grants, denials, revocation and restart requirements must be checked on a physical Mac. Hosted tests use injected permission/window providers; production permission requests remain explicit.
- All 13 gestures need mouse/trackpad acceptance at all corners, including hover/hold timing, middle-button availability, scroll momentum, modifiers and cooldown. Events pass through; underlying apps and macOS Hot Corners may also respond. Practice uses the same recognition but executes no action.
- Profiles are snapshots. Editing current bindings does not automatically rewrite a saved snapshot; use Update from Current. Unmatched apps retain the selected profile. Imports add reviewed snapshots only; group bindings refer to local group IDs, so an imported group may need reassignment.
- App exclusions suspend recognition, not an action already completed. Canceling a Shortcut stops the CLI but cannot undo earlier effects. URL-group cancellation stops remaining opens; already opened tabs stay open. Timed pause is session-only.
- Window controls depend on the target app exposing supported Accessibility attributes. Constrained windows, fullscreen Spaces and disconnected displays can refuse a change; errors are shown and rollback is attempted. Frame restore keeps up to eight frames for 16 windows per session. Hide/restore tracks up to 128 specific app instances and does not unhide apps that were already hidden.
- Actual Chrome/Safari/Finder Automation and blank Office/iWork/TextEdit documents need installed-app acceptance, including first-run and license dialogs. Desktop ChatGPT, Claude and Spotify must be installed. The Screenshot action opens Apple's toolbar; it does not capture unattended. Screen Saver does not guarantee screen locking.
- Launch at Login needs a real installed application and macOS Login Items approval. Tests inject Service Management; they do not register the test app. Shortcut-list/run tests do not run a personal Shortcut.
- Clipboard backup is bounded to 2 MiB and supported readable item types; unsupported lazy data produces an error before writing. Undo is one step, in memory only, and refuses a changed clipboard. Concurrent edits by another process cannot be made fully transactional by NSPasteboard. URL decoding is component decoding, not form-urlencoded decoding; JSON formatting preserves number text. Test pasteboards are private.
- Chrome history requires explicit selection and refresh. Read-only SQLite WAL coordination can create/update the transient `-shm` sidecar, without changing records or DB/WAL bytes. Real profiles, busy databases and macOS file-access restrictions need physical checks.
- Multiple/Retina/negative-coordinate displays, reconnects, Spaces/fullscreen, sleep, fast user switching and lock event order need physical hardware testing. Keyboard/VoiceOver, dark appearance, Reduce Motion, active monitoring performance and normal first-run memory also remain acceptance items.
- Native preview captures prove actual view rendering with explicit synthetic fixtures, not interaction with real accounts, permission panels or installed targets. The finite idle smoke measures a monitoring-disabled launch; it excludes WindowServer/GPU cost and active gestures.
- No telemetry, cloud AI, sync, background clipboard watcher, arbitrary shell binding or automatic network request is included. Explicit website/search/Shortcut actions can perform their named external effects.
